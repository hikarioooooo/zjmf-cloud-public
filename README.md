# 魔方云 3.9.42 安装站

先搭好自己的授权站，再运行安装命令。主控、计算节点使用同一条命令，安装时选择类型即可。

本包包含目前已集成的节点补配、自动续签服务检查、实例列表延迟修复和镜像目录修复。适配范围为 **3.9.42 的指定构建**；这不是 3.9.22 等旧版本的升级包。

## 1. 部署安装站

1. 新建 PHP 网站，使用 PHP 7.2 或以上版本，启用 `openssl` 和 `allow_url_fopen`。
2. 将本目录中的文件、文件夹原样上传到网站根目录，保留 `other/` 和 `ext/` 层级。
3. 把 `nginx-rewrite.conf` 的规则加入该站点的 Nginx 配置，保留原有 PHP 解析配置；已有相同 `location` 时合并，不要重复添加。
4. 打开网站首页，能看到三步安装教程即可。再访问 `/site.json`，应显示 `product_version: 3.9.42` 和客户端校验值。

首页会根据实际访问域名生成命令，**不用修改脚本里的域名**。安装站也需要 PHP，不能当作纯静态网站部署。

## 2. 部署独立授权站

1. 下载本目录的 `zjmf_auth_api.zip`，或使用单独提供的授权站包。
2. 新建另一个 PHP 网站，上传包里的 `index.php`，配置 `伪静态.txt` 中的规则。
3. 启用 `openssl`、`allow_url_fopen`，允许 PHP 进程在网站根目录创建 `.zjmf-data/`，不需要设置 777。
4. 访问 `https://auth.example.com/health`，应返回 `status: 200`、`service: zjmf-cloud-auth`、`version: 3.9.42`。

授权站不需要数据库。安装时填写它的完整地址，例如 `https://auth.example.com/`。每位使用者都可以部署自己的授权站；主控和所属节点必须填写同一个地址。

## 3. 安装主控或节点

在要安装的服务器上使用 root 执行命令。下面仅是格式示例，**实际命令直接从你部署好的安装站首页复制**：

```bash
wget 'https://install.example.com/install-zjmf-cloud_new' -O install-zjmf-cloud_new && chmod +x install-zjmf-cloud_new && ./install-zjmf-cloud_new
```

按提示完成以下步骤：

1. 输入自己的授权站完整地址；校验通过才会继续。
2. 选择“主控”“仅计算节点”或“合并安装”。
3. 按原安装器提示填写信息。若要求授权码，本配套流程可使用 32 位大写十六进制标识，例如 `7D1C62A93F804BE69A5D28C041E7B936`，并保留该标识。
4. 等待安装后的授权处理结束，保存后台地址、账号和密码。单独安装的计算节点还需在主控中添加，并确认已连接。

主控最终应出现 `INSTALLATION_VERIFIED`；续签服务检查通过后出现 `NODE_AUTO_RENEWAL_READY`。正常计算节点适配完成时显示 `NODE_CLIENT_PREPARED`；使用 `--node-only` 补配完成时显示 `NODE_RECOVERY_PREPARED`。之后由主控处理绑定和续签。出现 `STOPPED` 表示未完成，不要只看原安装器打印的后台地址。

目标服务器需为 x86_64，安装入口沿用 CentOS 7.9 / CentOS Stream 8 环境。主控扩展匹配 PHP 7.2.24 NTS；不要把授权站支持的 PHP 版本范围当作主控扩展的版本范围。部分原版组件仍需从上游下载，本包不是离线安装包。

## 4. 节点断线、补配与续签

安装过程中网络配置可能让 SSH 断开。先重新登录，查看 `/var/log/zjmf-bootstrap/` 中最新日志；安装还在运行就等待，勿同时启动第二次安装。脚本处理了终端断开，但不保证服务器重启后自动续跑。

确认节点已装好、原安装进程已结束，但授权接入未完成时，在节点运行：

```bash
wget 'https://install.example.com/install-zjmf-cloud_new' -O zjmf-node-repair.sh && bash zjmf-node-repair.sh --node-only
```

填写与主控相同的授权站地址。此模式只处理已安装节点，不重跑原版安装和网络配置；仍未获得授权时，可在主控点击“下发授权”补救。日志可能包含安装时生成的密码，分享前先脱敏。

节点凭据单次有效七天，主控原生任务会提前自动续签，通常不需要手动处理。请保持主控、节点和授权站正常通信。主控显示的权益到期时间与节点七天凭据分别计算。详情见 [节点补配](node-recovery.md) 和 [自动续签](node-renewal.md)。

## 5. 已有安装和更换地址

已有 **3.9.42** 可重新下载并运行同一入口，脚本会跳过原版安装，继续检查和适配。更换授权站时，主控和节点都需运行并填写新地址，不能只改 PHP 配置。

检查已有环境时可加 `--check`；仅检查授权站可加 `--auth-test`。自动运行可明确指定地址：

```bash
./install-zjmf-cloud_new --auth-url 'https://auth.example.com/' --check
```

授权站更新时覆盖配套新版 `index.php`，保留已有 `.zjmf-data/`。不要混用来源不同的签名密钥和客户端。

## 6. 上传 GitHub

把本目录内容放到仓库根目录即可，README 会直接显示。包内保留了运行组件及可维护源码，未包含测试数据库、服务器账号密码、运行日志、备份和历史验收记录。

**GitHub 用于保存和分发文件，GitHub Pages 不能运行 PHP。** 正常使用时，把仓库内容部署到自己的 PHP 网站，再从网站首页复制安装命令。

如果从 GitHub Raw 下载入口，需要通过 `--source 'https://你的安装站域名/'` 指定已经部署好的 PHP 安装站。Raw 文件中的 `SOURCE=__SITE_URL__` 是模板占位符，直接执行且不指定来源会报 `Invalid source URL`。

不要提交部署后生成的 `.zjmf-data/`、`.zjmf-fix/`、数据库或日志。PHP 源码内包含本套配套签名密钥；公开源码后这些密钥也公开，不应将它们作为独有身份或访问权限的安全凭据。

## 文件说明与边界

| 文件或目录 | 用途 |
| --- | --- |
| `index.php` | 首页、动态安装入口和组件信息接口 |
| `install-zjmf-cloud_new` | 主控、节点通用入口模板 |
| `nginx-rewrite.conf` | 安装站 Nginx 路由 |
| `zjmf_auth_api.zip` | 与独立授权站包内容一致的授权站源码 |
| `other/` | 固定构建安装器、客户端包及配套源码，保留完整目录 |
| `ext/` | 兼容下载路径使用的 PHP 扩展 |
| `SHA256SUMS.txt` | 文件校验清单，Linux 下可运行 `sha256sum -c SHA256SUMS.txt` |

目前验证过指定构建的主控、节点接入、自动续签以及部分镜像完整下载；没有覆盖所有系统的全新安装、全部镜像启动及所有插件业务功能。节点续签通过受控测试验证，不等于长期不间断运行保证。随附插件不代表所有第三方插件和远端服务。

本套更新接口目前不分发旧版升级包。**3.9.22 → 3.9.42 的数据迁移尚未验收，不要用本安装入口替代版本升级。**
